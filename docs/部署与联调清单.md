# 部署与联调清单

## 请一次准备的资料

|项目|配置项或用途|从哪里取|
|---|---|---|
|企业 ID|`WECOM_CORP_ID`|企业微信管理后台的企业信息|
|回调 Token|`WECOM_TOKEN`|自建应用的接收消息配置，可新建随机值|
|43 位回调加密密钥|`WECOM_AES_KEY`|同一接收消息配置的 EncodingAESKey|
|企微自建应用 Secret|`WECOM_SECRET`|企业微信自建应用详情，在「微信客服 → 可调用接口的应用」中授权该应用|
|测试客服帐号|选定开启 API 管理的帐号，准备测试二维码或入口链接|微信客服设置。确认对应的接待人员在自建应用的可见范围内|
|回调域名|`PUBLIC_DOMAIN`，例如 `collector.example.com`|已有域名或新建子域名，DNS 指向部署主机|
|部署主机及出口地址|开放 TCP 80、443，固定公网出口 IP 登记到企微可信 IP|主机或容器运行环境|
|坚果云目标路径和凭证|启用同步时提供 `DAV_URL`、`DAV_USER`、`DAV_PASS`|目标目录需先创建。密码使用坚果云授权的 WebDAV 应用密码|
|失败重放令牌|需要值守人员操作时设置 `ADMIN_TOKEN`|可新建随机值，留空时接口关闭|

可以先提供企业 ID、客服测试入口、域名、主机和公网出口 IP。Token、加密密钥、Secret 和 WebDAV 应用密码请通过部署环境的密钥配置或现有安全渠道交接。使用 Compose 时将值填入服务器的 `.env`，必要时按 dotenv 语法用单引号保留值里的 `$` 等字符。

以上按企业微信内的微信客服接入流程列出。先把自建应用加入「可调用接口的应用」，再填写它的 Secret。参见 [企业微信回调配置](https://developer.work.weixin.qq.com/document/path/90930)、[微信客服接收消息和事件](https://developer.work.weixin.qq.com/document/path/94670) 和 [企业微信基础应用 Secret 调整](https://developer.work.weixin.qq.com/document/51165)。

## 部署顺序

1. 在企微后台授权自建应用及选定的客服帐号。在部署机配置域名解析、防火墙和企微可信出口 IP。保持一份采集服务实例使用同一组 Vault 和 SQLite 卷。
2. 在仓库根目录执行 `cp .env.example .env`，填入必需配置。WebDAV 三项一起填写或一起留空。若更改 `CALLBACK_PATH`，企微回调 URL 也要使用该路径。
3. 执行 `docker compose --env-file .env -f deploy/docker-compose.yml up -d --build`。Caddy 提供 HTTPS，只将配置的回调路径转给采集服务。
4. 在自建应用的「接收消息」中填写 `https://<域名>/webhook/kf`、Token 和 EncodingAESKey，选择接收「微信客服消息和事件」，保存并检查 GET 校验结果。再用指定客服帐号的二维码或入口发测试消息。
5. 查看 `docker compose --env-file .env -f deploy/docker-compose.yml logs -f collector`。笔记、资源和 SQLite 状态分属 `vault` 与 `state` 两个卷。

## 配置默认值

|变量|默认值|用途|
|---|---|---|
|`CALLBACK_PATH`|`/webhook/kf`|公网回调路径|
|`LISTEN`|`:8080`|回调监听地址|
|`INTERNAL_LISTEN`|`127.0.0.1:8081`|本地运维监听，Compose 中限定在容器网络|
|`VAULT_ROOT`|`./collect`|归档根目录，容器内为 `/vault`|
|`DATA_DIR`|`./data`|SQLite 和备份目录，容器内为 `/state`|
|`MEDIA_MAX_MB`|`20`|单个本地媒体上限，以 MiB 计|
|`DOUYIN_MAX_DURATION`|`10m`|抖音视频时长上限|
|`OFFICIAL_FETCH`|`false`|是否抓取公众号正文|
|`OFFICIAL_FETCH_TIMEOUT`|`8s`|公众号正文抓取总时限|
|`OFFICIAL_FETCH_MAX_IMAGES`|`20`|每篇正文图片上限|
|`OFFICIAL_FETCH_UA`|内置移动端 UA|可选覆盖公众号正文请求头|

## 真实环境验收

- 企微后台通过 GET 校验。微信侧连续发送三条文字，核对上海时间、条目顺序和单一当日文件。重启服务后向同一天追加。
- 发图片及公众号分享卡片，核对图片和封面在 `assets/` 中，并能在 Markdown 编辑器渲染。临时打开正文抓取，试一篇公开文章和一篇要求验证的文章。
- 发能访问及过期的抖音分享链接，分别检查下载结果和链接降级。样品按技术方案记录真实解析成功率。
- 打开坚果云目标目录，对照当天笔记和资源。创建包含新 `## HH:MM` 条目的冲突副本并触发一次当天同步，核对新条目进入主文件及副本进入 `.conflicts/`。有无法归属的修改时，保留两边原文，由人工决定如何合并。
- 按技术方案核对实际回调 P99、媒体成功率及连续三天运行表现。

## 恢复和排查

- SQLite 在 `DATA_DIR/backups` 按上海日期生成一致性快照，保留最近七天。恢复时先停服务、恢复 Vault，再把快照恢复为 `collector.sqlite`。同时移走损坏库遗留的 `collector.sqlite-wal` 和 `collector.sqlite-shm`，用恢复后的数据目录重新启动。
- 保持 Markdown 中自动生成条目的 HTML 注释完整。它们使重启后的追加和冲突合并能识别同一条消息。
- 内网 `GET /healthz` 检查 Vault 可写与状态库可读。用 `GET /metrics` 查看回调延迟、抖音分级与失败原因、落盘资源体积和磁盘可用空间。资源写入预留 32 MiB 给笔记等文件。
- 确认失败原因已排除后，用配置的 `ADMIN_TOKEN` 向内网 `POST /admin/replay/<msg_id>` 发送带 `Authorization: Bearer <token>` 的请求，成功排队返回 `202`。
- 同步依赖服务端支持 `MKCOL`、`PROPFIND`、条件 `PUT` 和 `MOVE`。已有 Markdown 使用强 ETag 防止覆盖并发修改；更新冲突会重试。
